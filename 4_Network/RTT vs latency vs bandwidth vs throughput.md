# RTT vs Latency vs Bandwidth vs Throughput

## 一句話總覽

- Latency：單向延遲（資料從 A 到 B 要多久）。
- RTT（Round-Trip Time）：往返延遲（A -> B -> A 一來一回）。
- Bandwidth：理論最大傳輸能力（管道多寬）。
- Throughput：實際有效傳輸速率（實際跑出來多快）。

## 快速比較

| 名稱                   | 定義                 | 常見單位    | 越大越好？     | 受什麼影響                         |
| ---------------------- | -------------------- | ----------- | -------------- | ---------------------------------- |
| Latency                | 單向傳輸所需時間     | ms          | 否（越小越好） | 距離、排隊、路由、設備處理時間     |
| RTT（Round-Trip Time） | 往返傳輸時間         | ms          | 否（越小越好） | Latency x2 + 回應端處理 + 路徑狀態 |
| Bandwidth              | 可提供的理論最大頻寬 | Mbps / Gbps | 是             | 線路規格、ISP 契約、網路設備上限   |
| Throughput             | 實際有效吞吐量       | Mbps / Gbps | 是             | 協定開銷、丟包、擁塞控制、RTT、CPU |

## 容易混淆的點

### 1. 高頻寬不代表低延遲

- 頻寬像「水管寬度」；
- 延遲像「第一滴水多久到」。
- 水管很寬，但很遠或塞車，延遲仍可很高。

### 2. Throughput 常小於 Bandwidth

- 理論頻寬是天花板；
- 實際吞吐量會被封包重傳、協定控制、路徑壅塞拉低。

### 3. RTT 跟 ping 的關係

- `ping` 常用來觀察 RTT（不是純單向 latency）。
