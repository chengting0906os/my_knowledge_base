# SQL Injection

## 如何產生

- 本質：把「使用者輸入」直接拼接進 SQL 字串。
- 當輸入未正確驗證/轉義，攻擊者可改變原本查詢邏輯。

## 為什麼參數化查詢能解決問題

參數化查詢把 **SQL 結構** 與 **使用者資料** 分兩階段送給資料庫：

1. 先送 SQL 模板（含佔位符 `?`），資料庫完成語法解析、建立執行計畫（**預編譯**）。
2. 再送實際資料，資料庫只把它當成「純值」填入，**不再重新解析語法**。

> **預編譯（Pre-compile）** 指的是：在資料填入之前，SQL 的語法結構就已解析並編譯成執行計畫，結構此時已固定。之後無論填入什麼資料，都只會被當成值處理，不會影響已確定的 SQL 結構。
> 類比：就像印好的表格，欄位固定，使用者只能在空格裡填內容，填什麼都只是文字，無法改變表格本身的結構。

```sql
-- 字串拼接（危險）
"SELECT * FROM users WHERE name = '" + input + "'"
-- 若 input = "' OR '1'='1"，查詢邏輯被改變

-- 參數化查詢（安全）
"SELECT * FROM users WHERE name = ?"  -- 結構固定
db.query(sql, [input])                 -- 資料只是值，不影響結構
```

攻擊者輸入的任何特殊字元（`'`, `--`, `;`）都只是「資料的一部分」，無法跳出值的語境去改變 SQL 指令。

## 如何預防

- 一律使用 **參數化查詢**（prepared statement），不要字串拼接 SQL。
- 對輸入做 **白名單驗證**（型別、長度、格式）。
- 資料庫帳號採 **最小權限**（避免使用 root/all privileges）。

## 一句話

SQL Injection 的根因是「把不可信輸入當成 SQL 指令的一部分」；核心解法是「參數化查詢 + 最小權限 + 輸入驗證」。
